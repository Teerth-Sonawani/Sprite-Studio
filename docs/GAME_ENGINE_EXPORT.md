# Game Engine Export

The processing pipeline is engine-independent. Exports are generated from an
approved manifest and never hand-edited as the source of truth.

## 1. Export profiles

Configured in `config/export_profiles.yaml`.

| Profile | Writes | Tested |
|---|---|---|
| `generic_png` | frame PNGs, manifest, animations.json | yes |
| `generic_sheet` | sheet PNG + sidecar, manifest, animations.json | yes |
| `godot_4` | sheet, `SpriteFrames` `.tres`, import notes | yes |
| `unity_2022` | sheet, slicing JSON, `.meta` template, import notes | yes |
| `aseprite` | refuses unless CLI is installed; no fake native project | no |

Run:

```powershell
python tools/export_asset.py manifests/moss_slime.manifest.json `
  --profile godot_4 --out exports/godot --force
```

A non-approved manifest is refused unless `--allow-unapproved` is used for a
demo. Do not ship a demo export as production.

## 2. Generic PNG

Writes individual frames grouped by role, the manifest and `animations.json`.
Use this when the engine can load individual textures or when you want the most
portable source. Keep the manifest next to the files; it contains hashes, pivot,
animation timing and provenance.

## 3. Generic sprite sheet + JSON

The sidecar is authoritative:

```json
{
  "sheet": { "width": 384, "height": 64, "columns": 6, "rows": 1, "cell_width": 64, "cell_height": 64 },
  "frames": [{ "index": 0, "x": 0, "y": 0, "width": 64, "height": 64, "duration_ms": 100 }]
}
```

Origin is top-left. Durations are milliseconds. Do not assume that the number of
columns is encoded in the image; read the sidecar.

## 4. Godot 4

The exporter creates:

- the sprite sheet PNG(s);
- `<asset_id>.tres` with `SpriteFrames` and `AtlasTexture` sub-resources;
- `import_notes.json`.

Example generated structure:

```text
[gd_resource type="SpriteFrames" format=3]
[ext_resource type="Texture2D" path="res://moss_slime__idle__sheet.png" id="1_texture"]
[sub_resource type="AtlasTexture" id="AtlasTexture_idle_0_0_64_64"]
atlas = ExtResource("1_texture")
region = Rect2(0, 0, 64, 64)
[resource]
animations = [{
"frames": [{"duration": 0.166, "texture": SubResource("AtlasTexture_idle_0_0_64_64")}],
"loop": true,
"name": &"idle",
"speed": 6.0
}]
```

Practical notes:

- Copy the whole exported folder into the Godot project, preserving relative
  paths, or update the `res://` paths.
- Set texture filtering to **Nearest** for pixel art, **Linear** for painted art.
- Verify the animation names, frame order and loop flags in the Godot inspector.
- If the sheet is re-exported, regenerate the `.tres`; do not hand-patch regions.
- The `.tres` uses `AtlasTexture` regions, so the sheet remains a single texture.

## 5. Unity 2022.3+

The exporter creates:

- the sheet PNG;
- `<sheet>.slices.json` with rects, animation groups and import settings;
- `<sheet>.png.meta` TextureImporter template;
- `import_notes.json`.

The JSON is an **import recipe**, not a native `.asset`. Unity's authoritative
sprite metadata is generated by its importer. Practical workflow:

1. Import the PNG.
2. Set Texture Type to **Sprite (2D and UI)**.
3. Set Sprite Mode to **Multiple**.
4. Open the Sprite Editor and apply the rects, or write a small editor script
   that reads the JSON.
5. Set Filter Mode to **Point** for pixel art.
6. Set Pixels Per Unit to match the project (100 is the template default).
7. Create animation clips from the sprite groups; set loop time per clip.

Review the `.meta` template before committing it; Unity may regenerate GUIDs.
Do not assume the template alone configures slicing.

## 6. Aseprite / LibreSprite

This workspace does **not** create native `.aseprite` files. If `aseprite` or
`libresprite` is installed, `tools/export_asset.py --profile aseprite` still
refuses, because a native project writer is not implemented. The honest path is:

- export PNG frames and sheets;
- open them in Aseprite/LibreSprite;
- author layers, tags and timing there;
- keep the native file as a separate editable source.

Do not claim an editable native file exists when it does not.

## 7. Pivots and coordinates

- Manifest pivot: pixels from the top-left, usually at the ground contact.
- Godot `AtlasTexture` region: top-left origin.
- Unity sprite pivot: normalized (0-1), usually bottom-centre for characters.
- Generic JSON: top-left origin, pixel rects.

Record the convention in the export notes. A pivot mismatch causes visible
misalignment even when the images are correct.

## 8. Pixel art import settings

- Filter: nearest/point.
- Compression: lossless or uncompressed; avoid block compression that smears
  hard edges.
- Mipmaps: off unless the game genuinely needs them.
- Sprite atlas padding: at least 1px, more if filtering/bleeding is observed.
- Pixels Per Unit: consistent across the project.
- Snap: enable pixel snapping in the camera/import settings where appropriate.

## 9. Export validation

- [ ] Manifest QA status is APPROVED (or export explicitly marked demo).
- [ ] Every file listed in the manifest exists.
- [ ] Sheet dimensions match the sidecar.
- [ ] Frame count matches the animation spec.
- [ ] Pivot/ground contact is correct in-engine.
- [ ] Animation names and loop flags match the design.
- [ ] Transparency survives import.
- [ ] Pixel art filtering is nearest and no blur appears.
- [ ] Frame order is correct.
- [ ] The asset reads at in-game size in a real scene.
- [ ] Licences/provenance are recorded.

## 10. Rebuilding exports

Exports are generated artifacts. If the source asset changes:

1. Re-run technical + visual QA.
2. Regenerate the manifest.
3. Re-run the export with `--force`.
4. Re-import/verify in the engine.

Do not patch an export and leave the manifest stale. The manifest is the record
of what was approved.
